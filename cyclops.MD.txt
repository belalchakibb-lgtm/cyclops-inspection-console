# 0. RÈGLE ABSOLUE — CONTEXTE DU PROJET

Tu travailles sur le projet AQCS CYCLOPS.

Tu dois TOUJOURS conserver le contexte global du projet avant de modifier du code.

Ne transforme jamais le projet en une simple application chatbot.

CYCLOPS est un assistant technique industriel destiné à accompagner les activités d'inspection.

Le projet combine :

- procédures techniques
- NDT
- APL
- APE
- APVG
- recherche locale
- assistant IA
- animations / visualisations 3D
- interface bilingue FR/EN
- authentification
- aide contextuelle selon la méthode d'inspection

Les méthodes actuellement représentées sont :

- PT — Penetrant Testing
- MT — Magnetic Testing
- UT — Ultrasonic Testing
- RT — Radiographic Testing
- VT — Visual Testing
- APL — Appareils / équipements de levage
- APE — Appareils / équipements électriques
- APVG — Appareils / équipements sous pression
- OTHER

---

# 1. OBJECTIF FINAL

Construire une plateforme AQCS CYCLOPS professionnelle permettant à un inspecteur de :

1. sélectionner ou identifier une méthode d'inspection ;
2. consulter rapidement la procédure correspondante ;
3. comprendre les étapes de contrôle ;
4. consulter les références/codes disponibles ;
5. visualiser une représentation animée de la méthode ;
6. rechercher localement dans la base de connaissances ;
7. poser une question à l'assistant IA ;
8. recevoir une réponse contextualisée par rapport à la méthode ;
9. identifier les sources utilisées ;
10. distinguer clairement :
   - procédure AQCS
   - référence normative
   - information générale
   - réponse générée par IA ;
11. fonctionner autant que possible même lorsque l'API IA est indisponible.

# 4. ASSISTANT IA ACTUEL

Le frontend peut envoyer une requête vers :

POST /api/ask

avec notamment :

{
  q,
  lang,
  method,
  history
}

Le backend (server.mjs) utilise NVIDIA NIM (NVIDIA_API_KEY) ou Anthropic (ANTHROPIC_API_KEY).

Depuis la v1.1 :

- le navigateur n'envoie plus que q, lang, method, history et éventuellement une image ;
- le prompt système est construit UNIQUEMENT côté serveur (le navigateur ne peut plus le modifier) ;
- le serveur cherche lui-même les passages pertinents (kb.mjs) et les envoie à l'IA avec des étiquettes [S1], [S2]… ;
- la réponse renvoie la liste des sources (type, document, section, révision) affichée sous chaque réponse ;
- la langue demandée est imposée à l'IA ;
- les échanges sont journalisés dans data/audit.jsonl (désactivable : AUDIT_LOG=off).

Le système prompt indique que l'assistant :

- aide sur les méthodes NDT ;
- aide sur APL ;
- aide sur APE ;
- aide sur APVG ;
- répond en français ou anglais ;
- donne des indications générales ;
- doit demander une vérification par rapport au code actuel ;
- doit orienter vers Level 3 / superviseur en cas de doute critique.

# 6. RÈGLE IMPORTANTE POUR L'IA

L'assistant ne doit jamais inventer une exigence normative.

Il doit distinguer :

### SOURCE AQCS

Information provenant des procédures internes AQCS.

### NORME / CODE

Information provenant d'un code ou standard identifié.

### INFORMATION GÉNÉRALE

Connaissance générale qui n'est pas présentée comme une exigence AQCS.

### IA

Interprétation ou explication générée.

---

# 7. COMPORTEMENT ATTENDU DE L'IA

Exemple :

Utilisateur :

"J'ai une indication UT de 42 mm, +6 dB et longueur 8 mm."

L'IA ne doit pas immédiatement dire :

"Accepté"

ou

"Rejeté".

Elle doit vérifier le contexte disponible.

Elle peut demander :

- épaisseur
- matériau
- type de soudure
- code applicable
- édition du code
- niveau d'acceptation
- procédure applicable
- localisation de l'indication
- autres informations nécessaires

Puis expliquer ce qui peut être déterminé avec les données disponibles.

- npm run check : vérification de syntaxe de tous les fichiers JS.

## v1.2 — 2026-11-03

### UT — Simulateur de détecteur de défauts (Phase 7 / formation)
- Nouveau fichier cyclops-utsim.js, affiché sous la page UT (bloc « Simulateur de détecteur de défauts »).
- A-scan simulé : palpeur 0° / 45° / 60° / 70°, gain (réf. + dB), base de temps, porte A, courbe DAC et 20 % DAC, déplacement du palpeur (vers la soudure et le long), balayage automatique.
- Lectures : parcours, profondeur, distance en surface, position depuis l'axe, amplitude, dB / DAC, n° de parcours ; coupe de la soudure avec faisceau et position du réflecteur ; dynamique d'écho.
- Bibliothèque de 9 indications (fissure, manque de fusion, manque de pénétration, soufflure, nid de soufflures, laitier, géométrie de racine, caniveau, dédoublure) : aspect à l'écran + situation « Refusé » et « Non refusé » avec la raison.
- Exercice d'entraînement : indication cachée aléatoire, l'inspecteur choisit le type et la décision, score.
- Règles d'acceptation = règles de formation (inspirées ASME VIII App. 12, SA-578, UW-35), clairement signalées « à vérifier ». Modèle physique simplifié, pas un appareil étalonné.
- Mode « Tracer la DAC » : 11 étapes guidées sur bloc d'étalonnage (trous génératrices T/4, T/2, 3T/4) : étalonnage base de temps, mise en place, 6 points (1er et 2e parcours) relevés par l'inspecteur avec contrôles (bon trou, écho maximisé, 80 % écran, gain de référence inchangé), tracé DAC + 50 % + 20 %, fiche d'étalonnage, correction de transfert, gain de balayage, vérifications périodiques (ASME V Art. 4, à vérifier).

### RT — Interprétation des radiogrammes (animation)
- Nouveau fichier cyclops-rtsim.js, affiché sous la page RT (bloc « Interprétation des radiogrammes »).
- Animation en 11 étapes sur négatoscope (lecture, pause, précédent / suivant, voix FR/EN) : conditions d'observation, identification, repères et couverture, repère « B », densité (densitomètre, plages −15 % / +30 %), IQI (fil essentiel), défauts de film, examen méthodique à la loupe, caractérisation, mesure et critères, décision et rapport.
- Atlas de 10 indications sur film (fissure, manque de fusion, manque de pénétration, soufflure, nid, laitier, tungstène, caniveau, retassure, excès de pénétration), chacune avec un cas « Refusé » et « Non refusé » et la raison.
- Valeurs = règles de formation (ASME V T-282 / T-276, ASME VIII UW-51, Annexe 4, UW-35), signalées « à vérifier ». Images dessinées, pas de vrais radiogrammes.

### 3D — Rendu réaliste WebGL (Phase 7)
- Nouveau moteur cyclops-gl.js basé sur Three.js r170 (copié dans vendor/, fonctionne hors ligne). Il reprend exactement l'API du moteur canvas (box, cyl, sph, ln, quad, txt, hud) : toutes les scènes, les ~40 modèles d'équipement et le cours passent en WebGL sans réécriture.
- Matériaux PBR (acier brossé, peinture industrielle, caoutchouc, cuivre, verre, Perspex, cordon de soudure strié, ZAT colorée), environnement studio (réflexions), ombres douces, sol d'atelier, anticrénelage, tone mapping ACES.
- Géométrie détaillée : arêtes arrondies, écrous, brides boulonnées ; traducteur UT (sabot, connecteur, câble) + détecteur portable avec A-scan ; yoke MT (bobines cuivre, pattes articulées, poignée) ; projecteur gamma, collimateur, balisage RT ; pont roulant (poteaux H, chemins, poutre caisson, chariot, moufle) ; armoire électrique (porte, joint, rails, disjoncteurs) ; réservoir (fonds elliptiques, soudures, piquage à bride, soupape, manomètre, berceaux).
- Interaction : caméra amortie (orbite, zoom, recentrage fluides), survol = surbrillance + nom, clic = fiche d'inspection + zoom sur la pièce, boutons 🧩 Éclater et ✂ Coupe.
- Performance : un seul contexte WebGL partagé, géométries en cache, résolution dynamique, rendu suspendu hors écran ou derrière une fenêtre, libération automatique des vues fermées. 60 im/s mesurés sur bureau et mobile.
- Repli automatique sur l'ancien moteur canvas si WebGL n'est pas disponible.
- Corrigé : erreur des particules MT au démarrage d'une phase de magnétisation (index négatif).
