# PROJECT: ZERO

A story-driven zombie survival adventure for Roblox. You play solo or in co-op with up to 4 players.

> **2037.** A miracle cell-repair trial turned a city into the infected. You wake up in an abandoned hospital with no memory and a wristband that reads **SUBJECT 00**.

This folder contains the whole game as code. The map, lighting, enemies, UI and story are all generated by scripts, so you don't have to model anything in Studio.

**Status:** Chapter 1 *The Outbreak* is fully built. Chapters 2–5 are designed (see [docs/STORY.md](docs/STORY.md)) but not built yet. See [docs/REPORT.md](docs/REPORT.md) for what's done and what's left.

## Play it in 5 steps

Roblox Studio only runs on **Windows or Mac**; there is no phone version, and Roblox requires Studio to publish a game. Everything else is already done for you. You need a computer once, for about 10 minutes.

1. **Download the place file.** On GitHub, open `project-zero/build/ProjectZero.rbxlx` and tap **Download raw file**.
   (Every push also builds it automatically: **Actions → PROJECT ZERO (Roblox) checks → latest run → Artifacts → ProjectZero-place**.)
2. On the computer, install and open **Roblox Studio** (free), then go to **File → Open from File…** and pick `ProjectZero.rbxlx`.
3. Press **Play** (F5). The server builds the hospital and city (about 1–2 seconds), and then the main menu appears.
4. To test saving in Studio, go to **Home → Game Settings → Security → Enable Studio Access to API Services**. You can only do this after step 5.
5. Go to **File → Publish to Roblox**, then follow [docs/PUBLISHING.md](docs/PUBLISHING.md) to set max players to 4, add the shop items (optional) and make the game public.

After it's published, you can play and test on your phone in the normal Roblox app.

### Testing checklist in Studio
| What | How |
|---|---|
| Phone/tablet controls | **Test → Device** emulator, e.g. iPhone 14 or iPad |
| Co-op (2–4 players) | **Test → Clients and Servers → 2 Players → Start** |
| Saving and loading | Turn on API access (step 4), play, stop, play again, then choose **Continue** |
| Purchases | Studio uses test purchases, so no Robux is spent |

## Project layout (Rojo-compatible)
```
project-zero/
├─ default.project.json        Rojo project (for PC developers)
├─ build/ProjectZero.rbxlx     Ready-to-open place (generated)
├─ tools/build_rbxlx.py        Rebuilds the place file from src/
├─ tools/lint.cjs              Static checks (syntax, globals, cross-module APIs, remotes)
├─ src/shared/       → ReplicatedStorage.Shared   data + networking shared by server & client
├─ src/server/       → ServerScriptService        Main + Services/ + World/ (map generator)
├─ src/client/       → StarterPlayerScripts       ClientMain + Controllers/ (UI, camera, input)
└─ src/character/    → StarterCharacterScripts    disables default fast health regen
```

### Architecture
- **Server-authoritative.** Damage, stamina, pickups, puzzles, story progress, purchases and saves all run on the server. Every RemoteEvent is rate-limited, type-checked and wrapped in `pcall` ([Net.lua](src/shared/Net.lua)).
- **Modular services** ([src/server/Services](src/server/Services)) talk to each other through one `Services` table, so there are no circular requires.
- **Data-driven content.** Story stages, dialogue, cinematics, documents, zombies, cosmetics and achievements live in `src/shared/*.lua`, so writers can edit them without touching game logic.
- **Procedural world.** [src/server/World](src/server/World) builds about 1,500 anchored, optimized parts at server start. No external models are used and no references can break.
- **Mobile performance.** Zombies share one AI loop (no script per zombie), templates are cloned instead of rebuilt, pathfinding only runs when the direct route is blocked, the zombie population is capped, far zombies despawn, and graphics quality has 4 levels.

### Rebuild after editing
```
python3 tools/build_rbxlx.py                         # → build/ProjectZero.rbxlx
npm i --no-save luaparse@0.3.1 && node tools/lint.cjs   # static checks
```
If you have Rojo installed on PC, you can run `rojo serve` and edit live in Studio.
